◎ docair

See how a project works: from the infrastructure down to the functions, drawn from its code and docs.

@if (error()) {

1

Generate the docs

Drop a project folder. docair reads doc blocks in any language, Markdown, Terraform, Helm and Dockerfiles. Nothing is stored; .env and Terraform state never leave your machine.

2

Look at it layer by layer

Switch between the infrastructure, the network, Kubernetes, the apps and the code, one concern at a time, and zoom into any box. Hide what you don't care about. Tests show next to what they cover.

3

Ask, and fix the docs

Ask how something works and follow the walkthrough, or tell docair what is wrong or missing: review the edit, apply it to the server's copy, and download the patch for your code. In your own project, docair serve applies it to the files, and docair ask and docair chat do the same in the terminal.

What docair reads: a doc block 
/***
 * Store a new order.

 * @flow    checkout 3 "the API stores the order"
 ***/

Blocks open with /***, #*** or <!--***, whatever the language. Tags say what a part is, what it calls, reads and writes. The full format is in docs/SPEC.md.
